## 证据，而不是声明

| 工程领域 | 一个真实系统应该证明什么 |
|---|---|
| **领域建模** | 业务规则是明确的系统契约，而不是隐藏在 UI 中的假设 |
| **后端完整性** | 无效或被操纵的操作会被服务器拒绝 |
| **安全与隐私** | 公共表面只暴露运营真正需要的信息 |
| **工作流设计** | 状态和转换代表真实运营过程 |
| **可靠性** | 回归测试编码重要的不变量和失败模式 |
| **交付** | Staging、发布、可观测性和连续性都是产品的一部分 |
| **成熟度** | 原型、试点、生产和扩展被诚实区分 |
