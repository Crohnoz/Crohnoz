## 运营原则

1. **在选择架构之前先理解真实运营。**
2. **降低实际使用系统人员的认知负担。**
3. **将安全、隐私和连续性视为架构问题。**
4. **小步交付、观察使用、衡量摩擦并持续改进。**
5. **公开展示能力，同时保护专有实现。**
